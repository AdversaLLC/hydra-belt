## Architecture: Hydra Cortex

One router becomes the stack's nervous system: a three-tier local dispatcher that reads a probe-verified index, wakes only the right skills and memories in ~200 tokens, arbitrates the session-start collision, and turns its own dispatch log into the fitness signal that finally unfreezes hydra-evolve.

### The 20 angles are not 20 features — they are the organs of ONE nervous system whose brain is the router. Today the stack "routes" by dumping 9,928 words of frontmatter (~13k tokens) into every session and letting the main model guess, while four skills brawl over the session-start slot and hydra-evolve sits frozen because it has no score to act on. Hydra Cortex inverts this: the router (the existing, already-verified `hydra-router/scripts/router.py` BM25 engine) becomes the single afferent nerve every request passes through, and the other 19 angles are either (a) what the router READS to decide, (b) what the router DOES at the moment of dispatch, or (c) the feedback loop that measures the router and feeds hydra-evolve.

Read the stack top-to-bottom as one signal path. A prompt arrives. Before the model thinks, a UserPromptSubmit hook runs the router. The router first consults GROUND TRUTH (Layer 0): caps.json tells it llama.cpp is present but disk is volatile (so it may wake the planner but must never propose a multi-GB download), the integrity ledger tells it which skills are authentic and un-quarantined, and the lockfile guarantees the index it is about to read is the one that scored 98%. ### Layers
- **L0 — Ground Truth (Substrate)** — Answers 'what machine, what's installed, is it authentic, can I restore it' as [V]-grade facts the router reads before ranking. A boot_id-stamped caps.json (probe-verified, self-invalidating on live-USB reboot) tells the router llama.cpp is present but disk is volatile; an integrity ledger hashes/pins every skill and quarantines drift; a hash-pinned lockfile makes the whole stack one-command restorable and its restore is accepted only when the router re-reproduces its 98% golden score. The router becomes physically incapable of dispatching to a missing, tampered, or unauthenticated tier. · _angles:_ cross-runtime, tier-reconciliation, supply-chain, reproducible-bundle
- **L1 — The Index (Corpus)** — The single canonical parse of all 104 skills — the routing table the router consumes and the ONLY place descriptions live. Two-tier split: ~20-word routing stubs stay hot (~2.5k tokens), full descriptions + trigger phrases + deduped bodies move to a cold armory the frontmatter dump never scans. A CONDENSE pass strips verbatim duplication (which is IDF poison), an ownership DAG assigns each orchestration concern exactly one owner to break the four-orchestrator tie, and a lifecycle registry redirects deprecated names and tombstones retired ones so the corpus can shrink without breaking any of the 381 cross-references. · _angles:_ description-compression, condense-automation, orchestration-boundaries, lifecycle-deprecation
- **L2 — The Router (Core / Center)** — The dispatcher itself, wired as a UserPromptSubmit hook. Three retrieval tiers (BM25 floor → static-embedding paraphrase tier → llama.cpp planner on ambiguity) rank the L1 index; each score is multiplied by a human-approved persona prior (clamped [0.80,1.25], so it re-orders near-misses but can never bury a strong lexical match); then memory fusion folds in matching landmines/lessons keyed on query-tokens ∪ shortlisted-skill-names. Output is one ~150-300 token dispatch brief injected before the model thinks — replacing the 13k-token load. · _angles:_ router-tfidf-fallback, router-model, user-model, router-memory-fusion
- **L3 — Boot Arbitration** — The one place the router decides WITHOUT a model. A declarative boot manifest resolves the four-way focal/napkin/theorist/wisdom-memory session-start collision into one topologically-sorted, read-only, veto-aware spine, injected deterministically by a SessionStart hook. A tension lint scans all 104 frontmatters and exits nonzero on any second always-on claim, so the constitution's most-violated rule becomes a failing exit code instead of a sentence. The manifest schema is the router's routing-table spine — the router can never sanction an activation the manifest forbids. · _angles:_ activation-arbitration, tension-detector
- **L4 — Memory (Persist + Recall)** — The archive the router's fusion tier reads, made self-filling and safe. Stop/SessionEnd hooks harvest every structured WISDOM/RETRO/FAILED-PATH block at session end (the harness banks the lesson even if the model forgets), git history back-fills years of [S] records, and every persisted byte passes a deterministic secrets/PII firewall (PASS/REDACT/BLOCK) that flips to STRICT when the router's shortlist touches credential-handling skills. The store feeds L2 fusion forward and is fed by the router's route log in reverse. · _angles:_ wisdom-autocapture, secrets-hygiene
- **L5 — Evidence & Fitness** — The feedback loop that measures the router and unfreezes hydra-evolve. A golden/adversarial gauntlet scores routing (hit@1/hit@3/MRR); a zero-token flight recorder joins the router's logged prediction to what actually fired (HIT/MISS, dead skills, over-triggerers); per-skill CI turns 104 skills of prose into a red/green board; and a red-team harness manufactures router misfires on purpose, filing each as a permanent hard-negative. Together these ARE the 'hydra-eval or drill-style behavior scores' hydra-evolve's EXPERIMENT phase requires and never had — every L0-L4 change is now gated by a number. · _angles:_ eval-harness, observability, skill-ci, adversarial-selftest

### Router spec

CORE: extend the already-shipped, already-verified `/home/paladin/.claude/skills/hydra-router/scripts/router.py` (BM25, k1=1.5, b=0.75, folder-name tokens weighted 3x, adaptive shortlist cut at 35% of top score, k≤5, measured 98% top-1 / 100% top-3 on 40 golden cases). Do not rewrite it — wrap it.

THREE TIERS, escalated only on doubt:
- Tier 2 (floor, zero-download, guaranteed): the existing BM25 engine over the L1 index (stubs + trigger phrases + cold-armory full text; full text costs index bytes, not context tokens). ~80ms, pure stdlib, works the minute it's installed and on a virgin live-USB before any model is fetched. This is the fallback contract every other tier degrades into.
- Tier 1.5 (embedding, paraphrase-robust): minishlab/potion-base-8M (Model2Vec static embeddings, ~7.5M params, ~30MB, MIT, CPU, no torch, ~1ms/encode). Per-skill vectors precomputed into the index; cosine top-k. Catches the exact misfires BM25 makes on natural phrasing (verified this session: "find hidden messages inside this photo" → BM25 ranks tsk-mmls over steganography-analysis). ~200-300ms cold via mmap'd safetensors, no daemon.
- Tier 1 (planner, judgment only): a Llama-3.2-1B-Instruct Q4_K_M GGUF served by the user's OWN llama.cpp build at /home/paladin/local-ai/llama.cpp/build/bin/llama-server, GBNF-grammar-constrained to strict JSON {action,target,arguments,reason}. Woken ONLY when Tier 2 and Tier 1.5 disagree or the request is multi-skill (flight-recorder data measures how often that is, before committing to the download). The same model does triple duty: runtime dispatcher, L3 tension adjudicator, and L5 adversarial generator.

PERSIST ON THE LIVE-USB: potion model + numpy/tokenizers wheels (~130MB one-time) under ~/.claude/router/model/; the GGUF (~700MB-1GB) under ~/models/. caps.json (L0) carries disk_volatile=true and persistent_disk — the router REFUSES to propose the GGUF download unless persistent_disk is confirmed, and always keeps BM25 as the floor. Model install is explicit, human-gated, never automatic.

SCORING PIPELINE per request: BM25/embedding raw score → × persona prior clamp(0.80,1.25) from the human-approved North Star (a 5x lexical lead survives any prior; an explicitly named skill pins to slot 1, priors bypassed) → adaptive cut at 35% of top, k≤5 → SHORTLIST.

SHORTLIST THRESHOLD: keep while score ≥ max(0.35 × top_score, tau_abs), where tau_abs is calibrated from the corpus's own 10th-percentile self-hit score (no magic number). Below threshold on everything → inject nothing (chitchat costs zero tokens).

MEMORY FUSION: memory query = request tokens ∪ shortlisted-skill-name tokens (routing output becomes retrieval keys, so a lesson tagged mcp/nodejs surfaces when mcp-builder tops the shortlist even if the prompt never says "npx"). Run wisdom.py's tf-idf over wisdom.jsonl, two lanes — LANDMINES (type=failed_path, injected first) and LESSONS (insight/decision/meta) — 3+3 cap, [V]/[S]/[U] and record age carried verbatim.

OUTPUT: one <hydra-dispatch> brief (~150-300 tokens, measured 602-2373 bytes) as UserPromptSubmit hookSpecificOutput.additionalContext — shortlist with scores, landmines, lessons, and the closing ledger-discipline line. Debounced by session_id: unchanged brief → say nothing.

LATENCY BUDGET: hook timeout 10s; BM25 ~80ms, embedding ~250ms, planner only-on-ambiguity ~1-2s. Every path exits 0 — telemetry or model failure can NEVER block a prompt.

Every dispatch appends {ts, prompt_hash (salted HMAC, never the text), shortlist, top, landmine/lesson counts} to route_log.jsonl — the flywheel that becomes L5's live eval corpus.

### Before / after

TOKEN TAX — Before: 9,928 words of frontmatter descriptions (~13.2k tokens) load into every session before the user types a word, and 61 skills self-declare triggers. After: L1 loads ~2.5k tokens of routing stubs (full text lives cold in the armory), and the L2 router injects a ~150-300 token dispatch brief only when something matches — chitchat injects zero. Net ~88% cut on the always-on tax, and the brief is richer than what it replaced (it carries scores, landmines, and lessons, not just names).

COLLISION — Before: four skills claim the always-on slot with no arbitration (focal 'Loads first whenever a session starts', napkin 'Activates EVERY session', theorist 'Activates EVERY session and stays active', wisdom-memory 'session starts on ongoing projects') — a logically unsatisfiable set that violates the stack's own 'never stack two auto-triggering spines' rule. After: L3's SessionStart hook injects ONE deterministic, veto-aware, read-only boot order from the manifest, and the tension lint exits nonzero on any second always-on claim. The rule stops being prose and becomes a failing exit code; napkin's boot-time write becomes curate-on-first-write, so cold start is idempotent.

EMPTY ARCHIVE — Before: .hydra/wisdom.jsonl was empty for the stack's entire life (5-8 records, all hand-typed this session), claude-mem (Tier 1) is not installed, and capture depended on the model remembering to run a script. After: L4's Stop/SessionEnd hooks harvest every structured lesson block at session end (the harness banks it even if the model forgot), git history back-fills years of [S] records, a secrets firewall guards every write, and L2's fusion quotes your own past dead-ends back to you before you repeat them — proven live: the store's first landmine ('MCP server as npx fails silently when Node absent') auto-surfaces the next time anyone types 'add an MCP server'.

NO EVAL — Before: hydra-evolve's EXPERIMENT phase requires 'hydra-eval or drill-style behavior scores' that do not exist, so its own first rule 'no evaluation, no evolution' freezes the entire EVOLVE loop. After: L5 produces four real, computable scores — golden hit@1/hit@3/MRR, flight-recorder routing precision over live traffic, per-skill CI red/green, and adversarial robustness that only goes up — and the router's route_log makes the eval corpus grow from real usage. Every L0-L4 mutation is now gated by a number, hydra-evolve's LEARN/DESIGN/EXPERIMENT/ANALYZE cycle can legally run, and the constitution is strengthened on every clause (red-first, assert-per-patch, human gate, [V]/[S]/[U], never-stack-two-spines) instead of weakened.

## Skeptic — biggest risk

Hook pile-up recreating the exact disease it treats, plus a hidden single point of failure. settings.json today has ZERO hooks — a clean, debuggable, model-native routing path. Nearly every angle bolts an automatic shell hook (UserPromptSubmit / SessionStart / Stop / PostToolUse / PreToolUse) onto every prompt: router dispatch, memory fusion, wisdom harvest, flight-recorder x3, secrets guard, capability probe, boot arbiter, lifecycle. Installed together they (1) recreate the 'many things claim the automatic slot with no arbitration' problem the redesign set out to kill — now in undebuggable shell instead of readable prose, with no arbiter for the hooks themselves; (2) stack cumulative Python cold-start latency onto every keystroke on a slow live-USB; and (3) if the armory or description-compression angles land, make 96+ skills discoverable ONLY through a hook, so one traceback or a persistence-wiped reboot silently blinds Claude to most of its stack with no error surfaced — strictly worse than today's load-everything tax. And the meta-move itself — adding ~10 subsystems, 4+ new skills (hydra-eval/ci/lint/guard), and 6+ hooks — IS the constitution's named anti-pattern 'absorb-absorb-absorb, never condense,' executed at the architecture level. The stack ends up more capable on paper and markedly more fragile in practice.

## Skeptic — the missing 21st piece (governance)

A hook-budget / single-dispatcher-spine contract plus a master rollback and rollout order — the governance substrate all 19 angles silently assume but none build. Concretely: (a) exactly ONE UserPromptSubmit entry and ONE SessionStart entry in settings.json, each a thin dispatcher that calls sub-modules (route, recall, guard, telemetry) in a declared order with a hard per-hook timeout and mandatory fail-open (exit 0, empty stdout) so no automatic surface can ever block or blind a prompt; (b) `git init` on ~/.claude/skills so every mutation across every angle is atomically one `git revert` — the true assert-per-patch/human-gate safety net; and (c) a dependency-ordered rollout — measure first (observability backfill), subtract second (condense), arbitrate the spines third, and only then mutate descriptions/persona — instead of 19 parallel foundations with no sequence and no kill-switch. That governance layer, not any individual organ, is what keeps this redesign from failing exactly the way the constitution warns.
